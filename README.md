# st-setup

SillyTavern 角色卡的**建档引擎**。一套「开局向导 + 变量初始化 + 主角档案 + 第一条消息」的通用实现，多张卡共用，卡里只放数据与 URL。

**核心原则：引擎住在这里，数据住在卡里。**

- 引擎（本仓库）：`怎么建档` —— 写世界书、校验、回滚、发消息
- 配置（每卡一份）：`这张卡填什么` —— 白名单、派生公式、固定键、两种正文
- 数据（不进仓库）：`这张卡是什么` —— 模板 YAML、技能包、锚点文案

改向导不用重新导卡，不用开新档。

---

## 它解决什么

SillyTavern 卡的开场通常有三种做法，都有各自的坑：

| 做法 | 坑 |
|---|---|
| 预写两三条开场白 | 改一句要重写全篇；玩家没得选 |
| 开场里塞 HTML 表单，前端写进 `stat_data` | 两份数据各自维护；重读会清空变量 |
| 让 AI 第一轮「记住你填的」 | 模型会漏、会编 |

这套的做法：**建档即写入**。玩家点完，脚本把 initvar 条目整条替换、重读变量、写主角档案、发一条自述消息，再让 AI 接第一段。

## 用法

```js
import { createSetup } from 'https://testingcf.jsdelivr.net/gh/azoth8010/st-setup@<commit>/src/setup-entry.js';
import { 配置 } from './config.js';          // 本卡的配置
import { 模板, 模板版本 } from './templates.js';  // 本卡的三份 initvar 常量

const setup = createSetup({ 配置, 模板, 模板版本 });

// 玩家点「开始」时调用
await setup.写入({ 名字: '格罗姆', 玩家段, 起点: 'β-B' });
```

`写入()` 内部：

```
① 校验起点              → 不在 配置.锚点 里直接报错
② 写 initvar 条目        → 白名单填玩家段 → 派生 → 固定键验收 → 摘牌替换
③ 写主角档案             → 失败只告警，不阻断建档
④ 发建档消息 + /trigger  → 发过就跳过（chat 变量记标记）
```

## 配置写什么

| 字段 | 作用 |
|---|---|
| `卡名` | 日志前缀、备份键名 |
| `锚点` | 可选起点列表 |
| `initvar.标记` | 条目 comment 里用于识别的子串（默认 `[initvar]`） |
| `initvar.白名单` | 允许脚本写入的变量路径，名单外一律拒绝 |
| `initvar.派生(tree, 玩家)` | 派生值（上限、编号）。**引擎不猜公式** |
| `initvar.固定键` | 节点 / 里程碑的键名规则与合法状态 |
| `initvar.额外验收(tree)` | 本卡特有的校验（字段齐全、长度上限等） |
| `主角档案.条目名 / 位置 / 正文()` | 常驻条目怎么写 |
| `消息.正文()` | 第一条消息怎么写 |

完整示例见 `examples/manfan/config.js`。

## 设计上的几条硬规矩

**1. 先摘牌，再新建。**
替换条目不是「删了再建」，而是把旧条目改名成不含标记的名字（摘牌）→ 建新 → 成功后删掉摘牌那条。这样任何时刻都不会出现「零条目」或「两条并存」。

**2. 两条 initvar 会打架。**
MVU 扫的是**所有全局书 + 角色主书 + 附加书**里 comment 含 `[initvar]` 的条目，逐条往同一个对象里灌。所以必须全局唯一——引擎在写入前后各查一次。

**3. 重读之前先备份。**
「重新读取初始变量」会先清空再解析。带着坏模板去重读，玩家不是「建档失败」而是「变量全没了」。备份存 chat 变量，刷新仍在。

**4. 引擎不猜任何题材相关的东西。**
派生公式、字段名、正文措辞全在配置里。引擎只认路径和函数。

## 测试
